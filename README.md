# PeerAuth

A local page to generate shared TOTP codes for supplementary verification.

一个纯 HTML + CSS + JS 的页面，用来生成供两人或更多人共用的 TOTP 二维码。**不需要安装依赖、不需要构建、不需要联网**——直接双击 `index.html` 就能用，也可以把整个目录丢到任意静态托管上。浏览器必须支持 `crypto.getRandomValues`；安全随机源不可用或调用失败时会停止生成，不会降级使用 `Math.random()`。

## 使用场景与安全边界

参与者在同一台可信电脑前，本地离线打开页面，各自用手机扫描同一个二维码，确认验证码一致后关闭页面。页面不会主动上传密钥，也不会将密钥写入浏览器持久化存储。

验证码仅用于辅助核验，不能证明对方是真人或某个特定的人，不能抵御实时转发或原样回传。所有参与者共用同一密钥，因此无法通过验证码区分成员。涉及重要操作时，应通过事先约定的可信渠道另行确认。

配对电脑、离线文件来源和所有参与者的手机都需要可信。二维码和 Base32 文本包含长期有效的密钥，避免保存或分享其截图。关闭页面不会撤销已被复制的密钥；若密钥泄露，需要所有参与者重新配对并停止使用旧密钥。

## 文件结构

```
index.html     页面结构
style.css      样式（跟随系统深浅色）
js/totp.js     TOTP / SHA-1 / SHA-256 / Base32（内置实现）
js/qr.js       二维码编码（内置实现）
js/app.js      页面逻辑
```

## 为什么没有任何依赖

`type="module"` 脚本和 CDN 资源在 `file://` 协议下会被 CORS 拦截或需要联网，所以 TOTP 和二维码编码器都是内置的纯 JS 实现——「双击就能打开」这个前提才成立。

- `js/totp.js`：SHA-1 / SHA-256 / HMAC / Base32 / TOTP，全部手写，不依赖 `crypto.subtle`（个别浏览器会把 `file://` 当作非安全上下文而禁用）
- `js/qr.js`：完整二维码编码器（自动选版本、字节模式、Reed-Solomon 纠错、掩码择优）

## 为什么用 SHA1 而不是 SHA256

页面和二维码固定使用 SHA1，以保持与验证器默认设置一致。内置库支持 SHA1 和 SHA256，其他算法会显式报错。若以后调整页面算法，应同时验证二维码参数、页面验证码和目标验证器的兼容性，避免扫码后两边的验证码不一致。
